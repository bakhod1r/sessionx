# sessionx — Spec

**One line:** A Go session management library that collects a session from an
incoming request — who, from what device, from where — keeps its lifecycle
honest, and stores it in whichever backend the caller picked.

## Why this exists

The repo description already commits to it: *"Fast and secure session
management library for Go with pluggable storage, expiration, renewal, and
concurrent access support."* The repo is empty. This spec is the greenfield
design.

The differentiator over `gorilla/sessions` and `scs`: sessionx does not just
hold a bag of key/value data keyed by a cookie. It **collects** a session —
it records what opened it (via `uax` and `devicex` — brand, handset name,
OS, browser, and whether it is a person at all), where it came from, which
language was resolved for it (via `alx`), and the lifecycle state it is in
(via `enumx`'s FSM). An application gets a real "your active devices / sign
out everywhere" screen without writing that plumbing itself.

## Confirmed decisions

| Question | Decision |
|---|---|
| Shape | Go library. No service, no daemon. |
| Device data | Collected automatically from the HTTP request, with adapters for the top-10 Go web frameworks. |
| Storage | Four backends: in-memory, Redis, `database/sql`, stateless signed cookie. |
| Client parsing | `uax`, wired to `devicex` through its `Config.Device` hook. sessionx writes no parsing rules of its own. |
| Language | `alx` resolver, optional. Nil resolver means no locale is recorded rather than one guessed from the header. |
| `reqx` | **Not used.** The repo contains only a LICENSE — there is no code to import. |

## Dependency rule

The core module `github.com/bakhod1r/sessionx` depends on **four first-party
modules only**, each of them free of third-party code:

| Module | Its one job here |
|---|---|
| `uax` | reads the User-Agent, Client Hints and fetch metadata — browser, OS, bot, in-app WebView, automation, spoof score |
| `devicex` | turns a model code into a handset name, wired in through `uax.Config.Device` |
| `enumx` | holds the session lifecycle as a validated FSM |
| `alx` | resolves the session's language across URL, query, cookie and `Accept-Language`, with provenance |

No third-party dependency ever enters the core module. `uax` itself requires
`devicex`, which is the same module rather than a second copy of it.

Anything that needs a third-party dependency is a **separate Go module** in
the same repository, with its own `go.mod`:

- `sessionx/redis` → `github.com/redis/go-redis/v9`
- `sessionx/adapter/gin`, `/echo`, `/fiber`, `/iris`, `/beego`, `/fasthttp`

A caller who wants only the memory store and stdlib `net/http` pulls
`sessionx` plus those four first-party modules, and no third-party code at
all.

## The top-10 framework question, answered honestly

Ten frameworks do not need ten adapters. Four of them are plain
`http.Handler` plumbing and are served by the **core** middleware with no
extra code at all:

| # | Framework | Adapter needed |
|---|---|---|
| 1 | `net/http` (stdlib) | core — `sessionx.Middleware` |
| 2 | `go-chi/chi` | core — it is `http.Handler` |
| 3 | `gorilla/mux` | core — it is `http.Handler` |
| 4 | `julienschmidt/httprouter` | core — one-line `http.Handler` wrap |
| 5 | `gin-gonic/gin` | `adapter/gin` — `gin.HandlerFunc`, own module |
| 6 | `labstack/echo` | `adapter/echo` — `echo.MiddlewareFunc`, own module |
| 7 | `gofiber/fiber` | `adapter/fiber` — fasthttp ctx, own module |
| 8 | `kataras/iris` | `adapter/iris` — own module |
| 9 | `beego/beego` | `adapter/beego` — own module |
| 10 | `valyala/fasthttp` | `adapter/fasthttp` — own module |

Every adapter is thin by contract: it extracts `(userAgent, remoteAddr,
headers, cookie)`, calls the same core `Collector`, and writes the cookie
back. No session logic lives in an adapter. That is what makes ten of them
maintainable.

`alx` already ships adapters for exactly those six frameworks, each as its
own module. sessionx copies that layout rather than inventing a second one,
so a contributor who knows one repository knows the other.

`uax` also ships middleware for `net/http`, gin, echo and fiber. sessionx
does not wrap it: the two middlewares answer different questions — uax's
attaches a parsed client, sessionx's attaches a session — and an application
that wants both composes them. sessionx calls uax directly, so using
sessionx alone never requires installing uax's middleware too.

## Domain model

### Session

```go
type Session struct {
    ID        string            // opaque, 256-bit, base64url
    UserID    string            // caller's subject; empty for anonymous
    Status    Status            // enumx-validated lifecycle state
    Device    Device            // what hardware and software opened it
    Client    Client            // what kind of thing opened it
    Network   Network           // where from
    Locale    string            // resolved language tag, via alx
    LocaleSource string         // url | query | cookie | header | default
    Data      map[string]any    // caller's payload
    CreatedAt time.Time
    LastSeen  time.Time
    ExpiresAt time.Time
    RenewedAt time.Time
}
```

### Status — the enumx FSM

```
active  ──idle timeout──▶  idle  ──touch──▶  active
   │                         │
   │                         ├──absolute TTL──▶ expired
   ├──absolute TTL──▶ expired
   └──revoke──────────▶ revoked  ◀──revoke──┘
```

`expired` and `revoked` are terminal. The transitions are registered with
`enumx.RegisterTransitions`, so an illegal move is a returned error, not a
silently corrupted row.

### Device — the uax + devicex part

```go
type Device struct {
    Raw            string   // the User-Agent, verbatim
    Code           string   // model code, from Sec-CH-UA-Model or the UA
    Brand          string   // "Samsung"
    Name           string   // "Galaxy S10"
    Family         string   // product line, when known
    Type           string   // Mobile | Tablet | Desktop | TV | Console | Watch | Car | XR | EInk | Embedded | ""
    OS             string   // "Android" | "iOS" | "Windows" | "macOS" | ...
    OSVersion      string
    Browser        string   // "Chrome"
    BrowserVersion string
    Confidence     float64  // 0..1, 0 when nothing matched
}
```

`uax` does the parsing — 187 tested rules across browser, OS, bot, in-app
WebView and automation — and calls `devicex` through its `Config.Device`
hook to name the handset. sessionx writes no parsing rules of its own: it
flattens uax's result into the shape a session row stores.

**Why uax and not a regex here:** Chrome's User-Agent reduction is steadily
emptying the legacy string, and the platform and model now arrive in Client
Hints. A parser reading only the User-Agent gets quieter every year. `uax`
reads both, and reports which source an answer came from.

### Client — what kind of thing opened the session

```go
type Client struct {
    Kind           string   // Human | Bot | AICrawler | AIAgent | Tool | Automation | Unknown
    BotName        string   // "ClaudeBot", when one identified itself
    AppName        string   // "Instagram", for an in-app WebView
    AutomationName string   // "Playwright", when declared
    SpoofScore     float64  // 0..1, rises as the client's claims stop fitting together
}
```

A session and a person are not the same thing. Crawlers, CLI tools and
headless browsers all open sessions, and an application that cannot tell
them apart cannot rate-limit them apart either.

sessionx **records these and acts on neither**. What to do about a bot or a
suspicious client is application policy, and a library that silently blocked
traffic on a heuristic would be the wrong place for that decision.

**Rule inherited from devicex and uax:** never guess. An unrecognised
User-Agent produces a `Device` with `Raw` set and everything else empty —
not `"Unknown"`, not `"Other"`.

### Network

```go
type Network struct {
    IP        string  // the client address, after proxy resolution
    Forwarded string  // the X-Forwarded-For chain, verbatim, for audit
}
```

Proxy handling is **opt-in and explicit**: `X-Forwarded-For` is trusted only
when the caller configures `TrustedProxies`. A spoofable header is never
trusted by default.

## Store contract

```go
type Store interface {
    Save(ctx context.Context, s *Session) error
    Load(ctx context.Context, id string) (*Session, error)   // ErrNotFound
    Delete(ctx context.Context, id string) error
    ListByUser(ctx context.Context, userID string) ([]*Session, error)
    DeleteByUser(ctx context.Context, userID string) (int, error)
}
```

`ListByUser` is what makes the "active devices" screen possible and is the
reason it is in the interface rather than bolted on later.

The stateless cookie store is the honest exception: it cannot enumerate or
revoke server-side, so it returns `ErrUnsupported` for `ListByUser` and
`DeleteByUser` rather than pretending.

## Security requirements

- Session IDs: `crypto/rand`, 32 bytes, base64url, no PRNG.
- Store lookups compare IDs with `subtle.ConstantTimeCompare` where the
  backend does not already hash them.
- Cookie store payloads are signed with HMAC-SHA256 and verified before
  decoding. A tampered cookie is an error, never a partially-decoded session.
- Cookies default to `HttpOnly`, `Secure`, `SameSite=Lax`.
- Session ID is rotated on `Renew` — the fix for session fixation.
- A `Session` with `Status` `expired` or `revoked` never loads as valid,
  even if the backend still holds the row.

## Non-goals

- No authentication. sessionx does not verify passwords or issue tokens.
- No CSRF token machinery. That is a separate concern and a separate library.
- No server, no dashboard, no HTTP API.
- No User-Agent parsing of its own — client identity is `uax`'s job, device
  naming is `devicex`'s, and both stay there.
- No acting on `Client.Kind` or `Client.SpoofScore`. sessionx records them;
  blocking, throttling and challenging are the application's decisions.
- No content negotiation beyond recording the resolved tag — serving the
  translation is the application's job.

## Definition of done

- `go test ./...` green in every module, including the adapter modules.
- Core module's full graph (`go list -m all`) contains no third-party
  module: only `uax`, `devicex`, `enumx` and `alx`.
- Race detector clean: `go test -race ./...`.
- Every store backend passes the **same** shared conformance test suite.
- README with a runnable quickstart per framework.
